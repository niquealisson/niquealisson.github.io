Mobile E2E frameworkFramework de E2E mobile

visual-e2e

Mobile tests that read the screen like a user does: OCR + OpenCV, zero testIDs, zero sleeps.

Testes mobile que leem a tela como o usuário: OCR + OpenCV, zero testIDs, zero sleeps.

  • Problem: mobile E2E suites break on selectors and hard waits, and green tests can still miss real bugs.
  • What I built: a TypeScript layer on Appium where text is found by PaddleOCR and icons by OpenCV template matching, rendered straight from the app's own icon font.
  • Testing ideas: every action must carry an assertion, the assertion must be false before the action (so a tap that does nothing fails), and waiting means re-reading the screen, never sleep.
  • Runs against a real running app with simulated GPS routes. Inspired by Shopify Engineering's “98% stable” article.
  • Problema: suítes E2E mobile quebram por seletor e espera fixa, e teste verde ainda deixa passar bug real.
  • O que construí: uma camada em TypeScript sobre o Appium que acha textos com PaddleOCR e ícones com template matching do OpenCV, renderizados direto da fonte de ícones do próprio app.
  • Ideias de teste: toda ação precisa de uma asserção, a asserção tem que ser falsa antes da ação (toque que não faz nada falha) e esperar é reler a tela, nunca sleep.
  • Roda contra um app de corrida de verdade, com rotas de GPS simuladas. Inspirado no artigo “98% stable” da Shopify Engineering.

API test architectureArquitetura de testes de API

One REST API, two frameworksUma API REST, dois frameworks

  • Full coverage of a marketplace API generated from its OpenAPI spec, written twice: 43 Playwright tests and 75 Cypress tests.
  • Playwright side uses API Objects (one class per resource, 12 in total) and fixtures per role: user, admin and super-admin.
  • Cypress side uses cypress-plugin-api so request and response show up inside the runner, which helps whoever is reading the bug report.
  • Test cases and bugs follow a documented Testiny → Jira workflow.
  • Cobertura de uma API de marketplace gerada a partir da spec OpenAPI, escrita duas vezes: 43 testes em Playwright e 75 em Cypress.
  • O lado Playwright usa API Objects (uma classe por recurso, 12 no total) e fixtures por papel: usuário, admin e super-admin.
  • O lado Cypress usa cypress-plugin-api para request e response aparecerem dentro do runner, o que ajuda quem lê o bug.
  • Casos de teste e bugs seguem um fluxo documentado Testiny → Jira.
